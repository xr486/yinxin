## 一、背景与需求

用户明确的多版本隔离诉求：

1. **升版不级联**：在某个父 BOM 的上下文中对子件升版，只应影响"当前选定的 BOM 结构"，其他 BOM 里对该子件的引用、以及它作为顶层 BOM 的版本都不受影响。
2. **不同版本可同时被引用**：不同父 BOM 可以引用同一子件的不同 BOM 版本。
3. **概念澄清**（用户确认）：锁定的是 **BOM 结构版本**（`bom_headers_all.version`，"装什么"），不是**物料属性版本**（`sf_item_no`，"料号是什么"）。因此 **`sf_item_no` 不加版本字段**。

## 二、方案A设计

### 核心思想：行级版本锁定 + is_current 降级为"默认版本"

- `bom_lines_all` 新增 `component_bom_header_id`：**该行引用的子件，锁定使用子件的哪个 BOM 头（版本）**。
  - `NULL`（默认）= 跟随子件的默认版本（`is_current`），即改造前的"连接跟随"行为，**向后兼容**；
  - 非空 = 钉死使用该子件的指定版本，**不受全局默认版本切换影响**。
- `bom_headers_all.is_current` **保留**，语义从"唯一生效版本"降级为"**默认展示版本**"：只有未锁定的行才跟随它。
- 树状结构仍完全靠 `bom_lines_all.bom_header_id → bom_headers_all`（父头）建立，**现有外键体系不变**。

### 两个关键概念（避免混淆）

| 字段 | 语义 | 例子 |
|---|---|---|
| `bom_lines_all.bom_header_id` | **这一行属于哪个父 BOM 结构**（行归属，已有） | 151 = 78000020\|v1 的结构里的一行 |
| `bom_lines_all.component_bom_header_id` | **这一行引用的子件，用子件的哪个版本结构**（引用指向，新增） | 153 = 78000022\|v1 的头 |

**校验约束**：`component_bom_header_id` 只能指向"本行 `component_item` 自己的头"（代码按 `headerById` 解析，锁定头不存在时自动回退默认，绝不会锁到别的物料）。

## 三、数据库改动

已执行：

```sql
ALTER TABLE bom_lines_all
  ADD COLUMN component_bom_header_id INT(11) DEFAULT NULL
  COMMENT 'child BOM header lock (NULL=follow is_current default)'
  AFTER component_item;
```

回滚：

```sql
ALTER TABLE bom_lines_all DROP COLUMN component_bom_header_id;
```

可选索引（数据量大时）：

```sql
ALTER TABLE bom_lines_all ADD INDEX idx_comp_bomhdr (component_bom_header_id);
```

现有数据 `component_bom_header_id` 全为 NULL → 自动保持"跟随默认"行为，**无需数据迁移**。

## 四、代码改动点（BOMSetup.php）

### 新增辅助函数

1. `headerById($db, $id)`：按 `bom_header_id` 取 BOM 头（行级锁定解析用，带静态缓存）。
2. `resolveChildHeader($db, $line)`：子件行版本解析 —— 行锁定(`component_bom_header_id`)优先；NULL 或锁定头已不存在 → 回退 `latestHeader()`（默认版本）。

### 渲染（左树 / 右层级表 / 思维导图 三处一致）

| 函数 | 改动 |
|---|---|
| `getActiveLines()` | SELECT 增加 `component_bom_header_id` |
| `renderForest()` | 子件节点解析优先行锁定；`<li>` 新增 `data-parent-hdr-id`（父头 id，升版定位用）；递归 `$childItems` 携带 `lock_hdr` / `parent_hdr` |
| `renderHierarchy()` | `$childHdr = resolveChildHeader($db, $ln)`；递归传解析后的 `$childHdr['version']`，保证子件展开结构一致 |
| `buildMindmapTree()` | 新增第 5 参数 `$rootHdrId`（根头锁定）；缓存键改为 `料号#锁定头`（同一子件在不同父下锁定不同版本时不得共用缓存）；递归传行锁定 |
| 思维导图端点(`op=mindmap`) | `?version=` 先解析为根头 id 再传入 |

### 升版（父上下文升版 = 锁新版本）

- 右键菜单 URL 增加 `&parent_hdr=`（取自节点 `data-parent-hdr-id`）。
- 升版弹窗(`op=upgrade`)：读取 `parent_hdr`，写入隐藏域；带父上下文时说明文案提示"仅该父 BOM 的引用锁定到新版本，其他 BOM 不变"。
- `upgrade_save`：升版成功插入新 header 后，若 `parent_hdr > 0`：

```sql
UPDATE bom_lines_all SET component_bom_header_id = <新header_id>
WHERE bom_header_id = <parent_hdr>
  AND component_item = <升版子件> AND disable_date = 0
```

- 升版/复制 BOM 复制子件行时，`component_bom_header_id` **随行原样复制**（新版本结构继承旧版本的锁定关系）。

### 版本切换语义

- `set_current_version` 逻辑不变（UPDATE 全部 `is_current=0`，选中=1），但语义变为"**设为默认版本**"。
- UI 文案统一调整：
  - 确认框：说明"未锁定的引用跟随默认，已锁定的不受影响"；提示"在某父 BOM 中右键子件升版可只影响该父"。
  - 按钮「设为当前生效」→「设为默认版本」；下拉/列表的「当前生效/当前」标签 →「默认版本/默认」。

## 五、行为对比

| 场景 | 改造前 | 改造后 |
|---|---|---|
| 子件升版（在父 BOM 上下文） | 插新 header，引用仍全局跟随 | 插新 header + **该父的引用行锁到新版本**；其他父不动 |
| 渲染子件版本 | 全部 `latestHeader`（is_current） | **行锁定优先**，NULL 才用默认版本 |
| 设为默认版本 | 全局生效，所有父跟随 | 只影响**未锁定**的行；已锁定的引用不变 |
| 审核 | 基于 is_current | 基于版本自身，与是否默认无关 |
| 现有数据 | — | 全 NULL，行为不变（零迁移） |

## 七、已知限制与说明

- 历史脏数据头（如 `89050632` version=''）无版本号；新锁定流程不会锁到这类头，`resolveChildHeader` 对 version='' 的头按 `latestHeader` 兜底，安全。
- 已审核父 BOM 的**结构**（行增删/用量）仍被冻结；行锁定只影响"显示用哪个子件版本"，不影响审核冻结规则。
- `component_version` 字段（2026-08-17 遗留，未使用）仍保留在 `bom_lines_all`，与本方案无关，确认不需要后可单独 `DROP`。
