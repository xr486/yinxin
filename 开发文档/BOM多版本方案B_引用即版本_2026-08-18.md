# BOM 多版本：方案B（引用即版本）实现说明

> 日期：2026-08-18
> 涉及文件：`BOMSetup.php`、`bom_lines_all` 表
> 配套 SQL：`SQL_2026-08-18_bom_line_version_lock.sql`（新增迁移段）
> 替代方案：`BOM行级版本锁定方案A_2026-08-18.md`（本方案取代方案A）

## 一、为什么从方案A 改为方案B

用户明确三点业务诉求：

1. **切换版本不允许级联**：把某个 BOM 切到某版本后，其他位置的 BOM 引用关系**保持不变**。
2. **升版 = 仅插入新 header**：升版只创建新版本（未审核），**不改变任何现有 BOM 的引用关系**；"重新绑定"是显式行级操作。
3. 因此 **is_current（默认版本）概念废弃**——没有任何引用"跟随默认"，引用版本一律由**行级字段**决定。

方案A 的"可空锁定 + is_current 兜底"仍允许级联（NULL 行会跟随默认），不满足诉求 1；方案B 改为**引用即版本**：每个引用行必须显式绑定子件版本，从机制上杜绝级联。

## 二、核心设计：引用即版本

- `bom_lines_all.component_bom_header_id`（已加）：**该行引用的子件，显式绑定子件的哪个 BOM 头（版本）**。
  - 非空 = 绑定具体版本，**永不受其他操作影响**；
  - NULL = 仅允许"该子件本身没有 BOM 结构"（叶子/原材料）；有 BOM 的子件**不允许 NULL**（渲染兜底 latestHeader，但不作为业务常态）。
- **渲染**：父结构 = 当前查看的父头版本（`?view=&version=`，纯 UI 切换）；子件结构 = **行的绑定头**，递归展开一致（左树/层级表/思维导图）。
- **is_current 废弃**：字段保留在库里但不作为业务概念；"设为默认版本"按钮已删除；版本下拉 = 纯查看切换（不写库）。

## 三、数据库改动与迁移

```sql
-- 字段（此前方案A已加）
ALTER TABLE bom_lines_all
  ADD COLUMN component_bom_header_id INT(11) DEFAULT NULL
  COMMENT 'child BOM header lock (NULL=follow is_current default)'
  AFTER component_item;

-- 迁移：把"子件有 BOM 头但行未绑定"的行，按子件当前 is_current 版本补绑（已执行，7 行）
UPDATE bom_lines_all l SET l.component_bom_header_id = (
    SELECT h.bom_header_id FROM bom_headers_all h
    WHERE h.assembly_item_no = l.component_item
    ORDER BY h.is_current DESC, h.bom_header_id DESC LIMIT 1
)
WHERE l.disable_date = 0 AND l.component_bom_header_id IS NULL
  AND EXISTS (SELECT 1 FROM bom_headers_all h3 WHERE h3.assembly_item_no = l.component_item);

-- 回滚（恢复到方案A/老逻辑）
UPDATE bom_lines_all SET component_bom_header_id = NULL WHERE disable_date=0;
-- ALTER TABLE bom_lines_all DROP COLUMN component_bom_header_id;  -- 彻底回滚
```

迁移后：7 行有 BOM 的子件全部绑定；29 行叶子/无 BOM 子件保持 NULL（合法）。

## 四、代码改动点（BOMSetup.php）

| 区域 | 改动 |
|---|---|
| 辅助函数 | `headerById()` / `resolveChildHeader()`（行绑定优先，NULL 兜底 latestHeader）；`latestHeader` 保留（仅作兜底/迁移/引用默认值） |
| 渲染 | `getActiveLines` 带出绑定字段；`renderForest`/`renderHierarchy`/`buildMindmapTree` 子件一律按行绑定解析；思维导图缓存键 `料号#绑定头` |
| 新增引用 | `expandInsertBomRef` / ref 引用保存 / `new_save` 添加子件：INSERT 时自动绑定子件最新版本（有 BOM 时），叶子绑 NULL |
| 层级表 | 新增"子件版本"列（可列设置隐藏）：有 BOM 的子件显示 `vX`（可点击），叶子显示 —；点击弹出该子件全部版本供选择（`op=line_version` 弹窗）→ POST `set_line_version_bind`（校验绑定头必须属于该子件）→ 仅更新本行 |
| 升版 | `upgrade_save` **去掉自动锁父行**：仅插新 header + 复制行（绑定关系随行复制）+ 替代件；不动任何父行。弹窗文案同步更新 |
| is_current 废弃 | 删除"设为默认版本"按钮与 JS；版本下拉去掉"（默认版本）"标记；del_confirm 版本列表去掉"默认"标记；后端 `set_current_version` 分支保留但标注废弃（无前端入口） |
| 删除版本 | `deleteBOMRecursive` 删除头前，把引用该头的父行 `component_bom_header_id` 置 NULL（悬空绑定回退剩余版本） |

## 五、行为对比

| 场景 | 方案A | 方案B（当前） |
|---|---|---|
| 切换查看版本（下拉） | 纯 UI | 纯 UI（不写库） |
| 设为默认版本 | 改 is_current，NULL 行级联 | **已删除**（无此概念） |
| 子件升版 | 父上下文升版锁该父 | **仅建新版本，不动任何父行** |
| 父 BOM 换子件版本 | 无 UI（8-17 曾尝试被否） | **层级表行级"子件版本"切换**（仅影响该行） |
| 新增引用 | NULL 跟随默认 | **自动绑子件最新版本** |
| 级联 | 可能（NULL 行） | **机制上不可能** |
