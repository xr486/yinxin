## 一、整体架构概览

参考系统（以下简称"参考系统"）的图文档模块包含以下子页面：

| 子页面 | 菜单路径 | 说明 |
|--------|----------|------|
| 文件工作区 | 图文档管理 → 文件工作区 | 正常文档的主操作区（浏览/上传/编辑/归档/废止） |
| 文档模板 | 图文档管理 → 文档模板 | 模板库 |
| 文件日志区 | 图文档管理 → 文件日志区 | 操作日志 |
| **文件废止区** | 图文档管理 → **文件废止区** | 已废止文档的查看与恢复 |
| **文件回收站** | 图文档管理 → **文件回收站** | 已删除文件的还原与彻底清除 |
| 变更管理 | 图文档管理 → 变更管理 | ECN 工程变更 |

本文档聚焦 **文件废止区** 和 **文件回收站** 两个功能。

## 二、状态流转关系

```
                    ┌─────────────┐
                    │   正 常     │ ← 文件工作区主状态
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐  ┌────────┐  ┌─────────┐
        │   归 档   │  │  废 止  │  │  删 除   │
        │ (只读留底)│  │(禁用但可恢复)│  │(进回收站)│
        └──────────┘  └───┬────┘  └────┬────┘
                         │             │
                         ▼             ▼
                   ┌──────────┐  ┌─────────┐
                   │ 文件废止区 │  │文件回收站 │
                   │ (可恢复)  │  │(可还原/  │
                   │          │  │ 彻底删除)│
                   └──────────┘  └─────────┘
```

### 关键区别

| 维度 | 废止（Abolish） | 删除（Delete / 回收站） |
|------|-----------------|----------------------|
| **触发场景** | 文件不再使用但需保留追溯 | 用户主动删除文件 |
| **数据位置** | 原记录标记 `status='废止'` | 原记录标记 `status='已删除'` |
| **是否可恢复** | ✅ 可恢复为「正常」 | ✅ 可还原为「正常」 |
| **可否彻底清除** | ❌ 不支持彻底删除 | ✅ 支持彻底删除（物理或永久标记） |
| **特殊字段** | 废止时间、废止备注 | 删除时间、原位置路径 |
| **展示入口** | 独立「文件废止区」页面 | 独立「文件回收站」页面 |
| **左侧导航** | 目录树（与工作区相同） | 时间分类树（今日/昨日/本周/上周/本月/去年） |

## 三、文件废止区 — 详细设计

### 3.1 页面布局

```
┌─────────────────────────────────────────────────────────────────┐
│  面包屑: < 主页  >  文件废止区  [×]                              │
├──────────────┬──────────────────────────────────────────────────┤
│  📂 目录      │  文件名称:[________]  文件编码:[________] [🔍查询] [🔄重置] │
│  ├ 主目录    │                                                  │
│  ├ 主目录    │  [👁查看]  [🔴废止]  [+恢复]         [⚙][🗑][🖨]    │
│  └ 主目录    │  ┌────┬────────┬──────┬────────┬──────┬────┐     │
│              │  ☐  │ 序号   │文件名 │ 状态  │废止时间│废止备│...  │     │
│              │  ☐  │  1     │xxx   │🔴废止 │06-11  │ ...  │     │
│              │  ☐  │  2     │yyy   │🔴废止 │08-14  │ ...  │     │
│              │  ☐  │  3     │zzz   │🔴废止 │10-17  │ ...  │     │
│              │  └────┴────────┴──────┴────────┴──────┴────┘     │
│              │  [<1>] 到第[__]页  确定  共3条  20条/页            │
└──────────────┴──────────────────────────────────────────────────┘
```

### 3.2 左侧目录树

- **结构**：与「文件工作区」完全相同的目录树（doc_folder 表）
- **节点类型**：项目主目录 → 子目录 → 叶子节点
- **交互**：点击目录筛选该目录下的废止文件

### 3.3 搜索条件

| 字段 | 类型 | 占位符 | 说明 |
|------|------|--------|------|
| 文件名称 | text input | （空） | 模糊匹配 doc_name |
| 文件编码 | text input | （空） | 模糊匹配 doc_code |
| 查询 | button | 🔍 | 执行搜索 |
| 重置 | button | 🔄 | 清空条件并刷新 |

### 3.4 工具栏按钮

| 按钮 | 样式 | 功能 | 说明 |
|------|------|------|------|
| 查看 | 蓝色 👁 | 查看选中行的详情 | 单行或多行查看 |
| 废止 | 红色 🔴 | 对正常文件执行废止操作 | 在废止区也可再次执行（二次确认？） |
| + 恢复 | 绿色 + | 将废止文件恢复为「正常」状态 | 恢复后文件回到工作区可见 |
| 设置/删除/打印 | 图标按钮 | 辅助操作 | 导出、批量操作等 |

### 3.5 数据表格列定义

| # | 列名 | 字段对应 | 说明 |
|---|------|----------|------|
| 1 | ☐ | checkbox | 多选框 |
| 2 | 序号 | rownum | 行号 |
| 3 | 文件名称 | doc_name | 文件名（可排序 ↑↓） |
| 4 | 状态 | status | 固定显示 **「废止」**（红色标签） |
| 5 | 废止时间 | abolish_date | 执行废止操作的时间 |
| 6 | 废止备注 | abolish_remark | 废止时填写的备注原因 |
| 7 | 文件编码 | doc_code | 文件编码 |
| 8 | 大小 | file_size | 文件大小（KB/MB） |
| 9 | 创建者 | creation_by | 文件创建人 |
| 10 | 版本 | version | 当前版本号 |
| 11 | 创建时间 | creation_date | 文件最初创建时间 |

### 3.6 后端逻辑要点

```sql
-- 废止区查询条件（伪代码）
WHERE status = '废止'       -- 仅显示已废止的文档
  AND folder_id = ?         -- 按左侧目录筛选
  AND doc_name LIKE ?       -- 按名称模糊搜索
  AND doc_code LIKE ?       -- 按编码模糊搜索
ORDER BY abolish_date DESC  -- 按废止时间倒序
```

**废止操作**：
```sql
UPDATE doc_master 
SET status = '废止', 
    abolish_date = NOW(), 
    abolish_remark = ?,      -- 用户输入的废止原因
    last_update_by = ?, 
    last_update_date = NOW() 
WHERE doc_id = ?
```

**恢复操作**：
```sql
UPDATE doc_master 
SET status = '正常', 
    abolish_date = NULL,     -- 清除废止信息
    abolish_remark = NULL, 
    last_update_by = ?, 
    last_update_date = NOW() 
WHERE doc_id = ? AND status = '废止'
```

```
│  ├ 今日删除  │                                                  │
│  ├ 昨日删除  │  [+恢复]  [🟠彻底删除]           [⚙][🗑][🖨]      │
│  ├ 本周删除  │  ┌────┬────────┬──────────────┬──────┬────┬────┐ │
│  ├ 上周删除  │  ☐  │ 序号   │ 名称         │位置   │删除时│类型│...│
│  ├ 本月删除  │  ☐  │  1     │ test2.xls    │主目录/│2026-│文件│   │

└──────────────┴──────────────────────────────────────────────────┘
```

### 4.2 左侧导航 — 时间分类树

与废止区的目录树完全不同，回收站按 **删除时间** 分类：

```
所有文件
├── 今日删除      -- WHERE delete_date >= CURDATE()
├── 昨日删除      -- WHERE delete_date >= DATE_SUB(CURDATE(), INTERVAL 1 DAY) AND delete_date < CURDATE()
├── 本周删除      -- WHERE delete_date >= DATE_SUB(CURDATE(), INTERVAL WEEKDAY(CURDATE()) DAY)
├── 上周删除      -- WHERE ...
├── 本月删除      -- WHERE delete_date >= DATE_FORMAT(CURDATE(), '%Y-%m-01')
└── 去年删除      -- WHERE delete_date < DATE_FORMAT(CURDATE(), '%Y-%m-01')
```

**注意**：参考系统中出现了两组"所有文件"（可能含不同维度分类），实际实现只需一组即可。

### 4.3 搜索条件

与废止区相同：文件名称 + 文件编码。

### 4.4 工具栏按钮

| 按钮 | 样式 | 功能 | 说明 |
|------|------|------|------|
| + 恢复 | 绿色 + | 将删除的文件还原到原位置 | 还原后 `status` 恢复为「正常」，文件在工作区重新可见 |
| 彻底删除 | 橙红色 🟠 | 永久删除文件记录 | ⚠️ **不可恢复**！需二次确认弹窗 |

### 4.5 数据表格列定义

| # | 列名 | 字段对应 | 说明 |
|---|------|----------|------|
| 1 | ☐ | checkbox | 多选框 |
| 2 | 序号 | rownum | 行号 |
| 3 | 名称 | doc_name | 文件/文件夹名称（可排序 ↑↓） |
| 4 | 位置 | folder_path | 原所在目录路径（如：主目录/WHTEST/测试项目名称/软件开发/设计） |
| 5 | 删除时间 | delete_date / last_update_date | 执行删除操作的时间 |
| 6 | 类型 | type | 「文件」或「文件夹」 |
| 7 | 大小 | file_size | 文件大小 |

### 4.6 后端逻辑要点

```sql
-- 回收站查询条件（伪代码）
WHERE status = '已删除'       -- 仅显示已删除的文档
  AND (delete_date BETWEEN ? AND ?)  -- 按左侧时间分类筛选
  AND doc_name LIKE ?
  AND doc_code LIKE ?
ORDER BY delete_date DESC
```

**还原操作**：
```sql
UPDATE doc_master 
SET status = '正常', 
    last_update_by = ?, 
    last_update_date = NOW() 
WHERE doc_id = ? AND status = '已删除'
-- 同时写日志
INSERT INTO doc_log (doc_id, action, detail, operator, operate_time) 
VALUES (?, '从回收站还原', '', ?, NOW())
```

**彻底删除**：
```sql
-- 方案A（推荐）：永久标记删除（物理文件保留，记录不可见）
UPDATE doc_master 
SET status = '已彻底删除',    -- 或用一个特殊状态值
    permanent_delete_date = NOW(),
    permanent_delete_by = ?
WHERE doc_id = ? AND status = '已删除'

-- 方案B（激进）：级联物理删除（不推荐，无法追溯）
DELETE FROM doc_file WHERE doc_id = ?;
DELETE FROM doc_master WHERE doc_id = ?;
-- 同步清理关联表...
```

> **建议采用方案 A**：用特殊状态标记（如 `status='已销毁'`），保留数据库记录供审计追溯，仅在前端过滤掉这些记录。物理文件可定期由后台任务清理。

## 五、与现有 DocPLM.php 的对接方案

### 5.1 当前状态字段体系

当前 DocPLM.php 的 `doc_master.status` 已有：
- `正常` — 默认状态
- `归档` — 归档只读
- `废止` — 已有此状态！（当前代码已有废止逻辑）
- `已删除` — 已有此状态！（当前代码已有软删除逻辑）

**结论**：`status` 字段已支持「废止」和「已删除」，核心状态流转无需改表。但建议新增 `abolish_date` + `abolish_remark` 两个字段以完整记录废止信息（详见 5.3）。页面视图为纯新增，不修改现有逻辑。

### 5.2 新增页面方案

| 项目 | 说明 |
|------|------|
| **废弃区 URL** | `DocPLM.php?mode=abolition` |
| **回收站 URL** | `DocPLM.php?mode=recycle` |
| **菜单注册** | scripts 表新增两条记录；user_power 表新增两个菜单项 |
| **PHP 入口判断** | 在 PlmQuery 中增加 `$mode` 分支，类似现有的 `template` 模式 |

### 5.3 现有字段盘点（2026-08-17 实测）

`doc_master` 表当前字段（共 17 个）：

| 字段 | 类型 | 当前用途 | 废止/回收站可用性 |
|------|------|----------|-------------------|
| `doc_id` | int(11) PK | 主键 | ✅ |
| `doc_code` | varchar(50) | 文件编码 | ✅ 回收站表格列 |
| `doc_name` | varchar(200) | 文件名称 | ✅ |
| `doc_type` | varchar(50) | 文件类型 | ✅ 可用于区分文件/文件夹 |
| `folder_id` | int(11) | 所属目录 ID | ✅ |
| `item_no` | varchar(40) | 关联物料 | ✅ |
| **`status`** | **varchar(20)** | **状态（正常/归档/废止/已删除）** | **✅ 核心字段** |
| `check_status` | varchar(10) | 在库状态 | — |
| `current_version` | varchar(10) | 当前版本 v1 | ✅ 废止区显示用 |
| `is_template` | varchar(1) | 是否模板 Y/N | — |
| `remark` | varchar(300) | 通用备注 | ⚠️ 可复用为废止备注，或新增专用字段 |
| `created_by` | varchar(30) | 创建人 | ✅ 废止区「创建者」列 |
| `creation_date` | int(11) | 创建时间（Unix 时间戳） | ✅ |
| `last_update_by` | varchar(30) | 最后更新人 | ✅ |
| `last_update_date` | int(11) | 最后更新时间（**Unix 时间戳**，非 datetime） | ⚠️ 可复用为废止/删除时间 |

#### 需要新增的字段

| 字段 | 类型建议 | 用途 | 必要性 |
|------|----------|------|--------|
| `abolish_date` | int(11) | 废止操作时间（Unix 时间戳，与现有字段风格一致） | **建议新增** — 否则无法区分"废止时间"和普通更新时间 |
| `abolish_remark` | varchar(300) | 废止原因备注 | **建议新增** — remark 是通用备注，混用会丢失原备注信息 |

> **不新增也可行方案**：如果不想加字段，废止时间可复用 `last_update_date`（执行废止时更新的时间），废止备注可复用 `remark`。但这样会覆盖原有信息。

#### SQL（✅ 已执行 2026-08-17）

```sql
-- 新增（已执行）
ALTER TABLE doc_master ADD COLUMN abolish_date int(11) DEFAULT NULL AFTER last_update_date;
ALTER TABLE doc_master ADD COLUMN abolish_remark varchar(300) DEFAULT NULL AFTER abolish_date;

-- 回滚
ALTER TABLE doc_master DROP COLUMN abolish_remark;
ALTER TABLE doc_master DROP COLUMN abolish_date;
```
