# 达和项目管理模块使用说明与操作指导

版本：2026-08-15
适用系统：达和制造业管理系统（WAMP/PHP 版）

## 一、模块用途

项目管理模块用于把项目从模板设计推进到项目执行和过程跟踪，主要用于：

- 维护项目模板、任务模板和标准任务结构。
- 根据模板快速创建项目实例。
- 管理项目负责人、项目角色、任务执行人和计划时间。
- 管理任务上下级关系、前置依赖、输入和输出。
- 通过状态、进度、任务树、甘特图和操作日志跟踪项目。
- 保留状态变化、任务分配和重要操作记录。

## 二、进入方式

### 2.1 从主菜单进入

登录达和后，进入左侧菜单：

项目管理

常用菜单包括：

- 项目总览
- 项目模板
- 任务模板
- 项目实例
- 待启动项目
- 运行中项目
- 已完成项目
- 项目角色
- 项目流程
- 设置

如果菜单没有显示，可以直接访问：

http://localhost/dahe/ProjectManagement.php

实际部署时，将 localhost 替换为服务器地址。

## 三、首次安装和部署

### 3.1 安装前检查

确认以下条件：

1. Apache/WAMP 已启动。
2. MySQL 已启动。
3. 达和数据库已经导入。
4. config.php 中的数据库名、账号和密码正确。
5. 使用 admin 管理员账号进行首次初始化。

### 3.2 需要上传的文件

项目管理功能至少需要上传：

- ProjectManagement.php
- project_management/ 整个目录

如果主菜单也有更新，同时上传：

- index.php

不要只上传 CSS 或 JS 文件，因为页面逻辑、数据库操作和安装脚本都在上述文件中。

### 3.3 初始化数据库

第一次安装时，用 admin 账号访问：

http://localhost/dahe/project_management/install.php

安装脚本会执行 project_management/schema.sql，创建项目管理所需的数据表和默认配置。

主要数据表包括：

- pm_roles：项目角色
- pm_template_nodes：项目模板和任务模板节点
- pm_template_assignments：模板角色分配
- pm_template_dependencies：模板前置任务
- pm_projects：项目实例
- pm_project_roles：项目角色分配
- pm_tasks：项目任务
- pm_task_assignments：任务执行人和角色
- pm_task_dependencies：项目任务前置依赖
- pm_task_io：任务输入和输出
- pm_logs：操作日志
- pm_settings：项目管理设置

### 3.4 旧数据库升级

如果旧数据库没有“已暂停”状态，在 phpMyAdmin 中执行：

ALTER TABLE pm_projects
MODIFY status ENUM('TO_BE_START','STARTING','PAUSED','FINISHED')
NOT NULL DEFAULT 'TO_BE_START';

也可以直接执行：

project_management/migrate_paused_status.sql

执行数据库升级前必须先备份数据库。

### 3.5 权限检查

安装脚本会写入 scripts 和 user_power 权限数据。如果普通用户看不到菜单，请检查：

- 用户是否被禁用。
- 用户角色是否有项目管理权限。
- scripts 表是否存在 ProjectManagement.php。
- user_power 表是否有对应用户的项目管理权限。
- 修改权限后是否重新登录或刷新主框架。

## 四、推荐业务流程

建议按以下顺序使用：

1. 创建项目角色。
2. 创建任务模板。
3. 创建项目模板和任务结构。
4. 在模板中配置角色和前置任务。
5. 从项目模板创建项目实例。
6. 检查项目负责人、计划日期和任务结构。
7. 启动项目和任务。
8. 维护执行人、输入输出和实际进度。
9. 使用项目跟踪和甘特图查看进度。
10. 所有任务完成后，再完成项目。

## 五、项目总览

项目总览用于快速了解项目管理情况。

### 5.1 状态统计

页面显示：

- 全部项目
- 待启动项目
- 运行中项目
- 已暂停项目
- 已完成项目

### 5.2 我的未完成任务

显示当前登录用户被分配且尚未完成的任务。点击“查看全部”可以进入运行中项目的未完成任务列表。

### 5.3 最近项目

显示最近更新的项目，包括项目名称、负责人、状态、计划结束时间和任务完成比例。

## 六、项目角色

进入：项目管理 → 项目角色

### 6.1 新建角色

点击“新建角色”，填写：

- 名称：例如项目经理、设计负责人、工艺负责人、质量负责人。
- 备注：填写该角色的职责范围。

角色名称不能重复。

系统内置“项目负责人”角色不能删除；用户自定义角色可以编辑和删除。

### 6.2 角色使用范围

角色可以分配到：

- 项目模板节点
- 任务模板节点
- 项目实例
- 项目任务

角色是职责定义，具体执行人员需要单独选择用户。

## 七、项目模板

进入：项目管理 → 项目模板

项目模板用于定义可以重复使用的项目结构。模板树支持文件夹、项目节点和任务节点。

### 7.1 节点类型

- 文件夹：用于分类整理模板；下级只能建立文件夹或项目模板，不能直接建立任务。
- 项目模板：可以被创建为项目实例；下级只能建立任务。
- 任务：项目执行时需要完成的工作。

项目模板和任务节点下面都只能继续建立任务。只有类型为“项目模板”的节点可以创建项目实例。

### 7.2 新建模板节点

#### 没有选中节点

点击左侧顶部“新建”，弹窗中的“上级”默认为“根目录”。

#### 已选中节点

如果当前选中了 444，再点击顶部“新建”，弹窗中的“上级”会自动选择 444。

点击右侧“新建下级”，也会把当前选中节点作为上级。

弹窗中的“类型”会根据上级节点自动限制：

- 根目录或文件夹下：只能选择文件夹、项目模板。
- 项目模板或任务下：只能选择任务。

### 7.3 模板字段

- 类型：文件夹、项目或任务。
- 上级：决定节点在树中的位置。
- 编码：模板或任务的业务编码，建议填写。
- 名称：必填，建议使用明确的业务名称。
- WBS：工作分解结构编号，例如 1.1、2.3。
- 工期：预计工期，单位为天。
- 任务类型：普通任务、生产任务、评审任务、里程碑。
- 启动条件：手动启动、任一前置任务完成、全部前置任务完成。
- 排序：同级节点的显示顺序。
- 描述：工作内容、交付要求或注意事项。

### 7.4 模板操作

选中节点后可以：

- 编辑节点。
- 复制节点及下级结构。
- 上移或下移同级节点。
- 在当前节点下新建下级节点。
- 从项目模板节点创建项目实例。
- 删除没有下级节点的节点。

项目实例页面只能管理已经创建的项目及增补子任务，不能在项目实例页面再次创建项目实例。

删除有下级节点的模板前，必须先处理下级节点。

复制主要复制节点结构和基本字段，复制后建议重新检查角色和前置任务。

### 7.5 模板角色

在节点详情的“项目角色”区域可以配置角色和人员。创建项目实例后，可以根据实际项目重新调整人员。

### 7.6 模板前置任务

为任务节点设置前置任务：

1. 选中任务节点。
2. 在“前置任务”下拉框中选择前置任务。
3. 点击“添加”。

系统会阻止：

- 任务依赖自身。
- 跨模板库设置依赖。
- 形成循环依赖。

已配置的前置任务可以通过“×”移除。

### 7.7 引用任务模板

在项目模板节点详情中，可以从任务模板库引用任务模板。引用适用于复用标准任务组，例如评审、打样、验证或归档任务组。

## 八、任务模板

进入：项目管理 → 任务模板

任务模板用于维护可复用的任务组，例如：

- 新产品开发任务组
- 工艺评审任务组
- 模具制作任务组
- 质量验证任务组
- 文件归档任务组

任务模板的树形操作方式与项目模板基本一致，主要用途是被项目模板引用。

任务模板库中的层级规则为：根目录或文件夹下可以建立文件夹、任务模板；任务节点下只能继续建立任务。任务模板库中的节点不能直接创建项目实例。

## 九、创建项目实例

### 9.1 创建入口

1. 进入项目模板。
2. 选中类型为“项目”的模板节点。
3. 点击“创建项目实例”。

### 9.2 创建字段

- 项目编码：必填，不能重复。
- 项目名称：必填。
- 负责人：选择项目负责人。
- 计划开始：项目计划开始时间。
- 计划结束：项目计划结束时间。
- 项目描述：可以使用模板描述，也可以按实际项目修改。

创建后，项目状态默认为“待启动”，模板中的任务会生成到项目实例中。

### 9.3 创建后检查

建议检查：

- 项目编码和名称。
- 项目负责人。
- 计划开始和结束日期。
- 任务是否完整。
- 任务上下级关系。
- 前置任务关系。
- 执行角色和人员。
- 每个任务的计划日期。

## 十、项目实例

进入：项目管理 → 项目实例

### 10.1 项目筛选

左侧可以按以下条件筛选：

- 项目名称
- 项目编码
- 负责人
- 项目状态

状态包括待启动、运行中、已暂停和已完成。

### 10.2 项目状态

| 状态 | 颜色 | 含义 |
| --- | --- | --- |
| 待启动 | 灰色 | 已创建但尚未开始 |
| 运行中 | 蓝色 | 正在执行 |
| 已暂停 | 红色 | 暂时停止执行 |
| 已完成 | 绿色 | 项目已经完成 |

### 10.3 状态流转

- 待启动 → 启动项目
- 运行中 → 暂停项目
- 运行中 → 完成项目
- 已暂停 → 恢复运行

完成项目时，系统会检查是否还有未完成任务。如果有未完成任务，项目不能完成。

## 十一、任务树和任务操作

项目详情中的任务以树形结构显示。

### 11.1 折叠和展开

- 点击任务左侧的减号可以折叠下级任务。
- 点击加号可以展开下级任务。
- 点击“全部折叠”可以收起所有任务节点。
- 点击“全部展开”可以展开所有任务节点。

### 11.2 新建任务

点击“新建任务”，填写：

- 上级任务：根任务或已有任务。
- 编码：同一项目内不能重复。
- 名称：必填。
- WBS：建议填写。
- 任务类型：普通任务、生产任务、评审任务或里程碑。
- 启动条件：手动、任一前置完成、全部前置完成。
- 计划工期。
- 计划开始和结束时间。
- 排序。
- 任务描述。

点击任务右侧的加号，可以直接在该任务下新增子任务，弹窗会自动带入正确的上级任务。

### 11.3 编辑、移动和删除

打开任务详情后可以：

- 编辑任务信息。
- 上移任务。
- 下移任务。
- 删除任务。

有下级任务的任务不能直接删除，应先删除或调整下级任务。

系统会阻止把任务设置为自身或自己的下级任务，防止任务树形成循环。

## 十二、任务启动条件和状态

任务状态包括：

- 待启动
- 运行中
- 已完成

### 12.1 手动启动

不依赖前置任务，由用户直接点击“启动任务”。

### 12.2 任一前置任务完成

只要任意一个前置任务完成，就允许启动当前任务。

### 12.3 全部前置任务完成

所有前置任务完成后，才允许启动当前任务。

### 12.4 任务状态颜色

- 待启动：灰色
- 运行中：蓝色
- 已完成：绿色

## 十三、任务角色、依赖和输入输出

### 13.1 执行角色

在任务详情的“执行角色”区域：

1. 选择角色。
2. 选择用户。
3. 点击“分配”。

已分配的人员可以通过对应的“×”移除。

### 13.2 前置任务

在“前置任务”区域选择其他任务并点击“添加”。

已添加的依赖可以移除。系统会阻止跨项目依赖和循环依赖。

### 13.3 任务输入和输出

用于记录任务所需资料、文件、系统链接或交付物。

字段包括：

- 方向：输入或输出。
- 名称：资料或交付物名称。
- 文件或系统链接：文件地址或页面地址。
- 说明：版本、用途或验收要求。

不再需要的输入输出可以点击“移除”。

## 十四、项目角色和操作日志

### 14.1 项目角色

项目详情的“项目角色”页签用于配置项目级角色和人员，例如项目经理、客户接口人或质量负责人。

项目角色和任务执行角色可以分别配置。

### 14.2 操作日志

项目详情的“操作日志”页签会记录主要操作，包括：

- 创建项目
- 修改项目
- 项目状态变更
- 任务状态变更
- 角色分配和移除
- 前置任务添加和移除
- 输入输出添加和移除
- 任务移动和删除

日志用于问题追踪和责任确认，不建议直接修改数据库中的日志记录。

## 十五、项目跟踪

进入：项目管理 → 待启动项目、运行中项目或已完成项目。

### 15.1 待启动项目

可以查看待启动项目中的我的任务、我负责的项目和我创建的项目。

### 15.2 运行中项目

运行中项目分为：

- 未完成任务
- 已完成任务
- 我负责的项目
- 我创建的项目

### 15.3 已完成项目

用于查看已经完成的项目和完成任务记录。

### 15.4 已暂停项目

项目管理页面内部支持已暂停项目跟踪。直接访问：

ProjectManagement.php?view=track&status=PAUSED&scope=owner

如果主菜单没有显示已暂停项目，可以使用项目实例页的状态筛选查看。

## 十六、甘特图

甘特图入口在项目实例详情的“甘特图”按钮。

甘特图要求任务填写计划开始和计划结束时间。如果没有计划日期，系统会提示先设置计划时间。

甘特图颜色：

- 灰色：待启动
- 蓝色：运行中
- 绿色：已完成

甘特图用于查看计划和进度，不会自动替代任务状态操作。

## 十七、项目流程

进入：项目管理 → 项目流程

页面说明三阶段：

1. 待启动：创建项目，确认负责人、计划时间和任务依赖。
2. 运行中：执行任务，维护输入输出和实际进度。
3. 已完成：所有任务完成后关闭项目并保留日志。

## 十八、设置

进入：项目管理 → 设置

当前设置为项目管理日历：

- 双休
- 单休
- 无休

默认值为单休。修改后点击“保存设置”。

## 十九、常见问题

### 19.1 提示项目管理尚未安装

使用 admin 账号访问：

project_management/install.php

检查数据库连接和 pm_projects 表是否存在。

### 19.2 菜单没有项目管理

检查：

- index.php 是否为最新版本。
- scripts 表中是否存在 ProjectManagement.php。
- 当前用户是否有项目管理权限。
- 是否已经重新登录或刷新主框架。

### 19.3 创建项目时报编码重复

项目编码具有唯一性，请换一个没有使用过的编码。

### 19.4 项目不能完成

项目完成前，项目下所有任务必须为已完成。进入任务树检查未完成任务。

### 19.5 任务无法启动

检查启动条件和前置任务：

- 任一前置任务：至少一个前置任务完成。
- 全部前置任务：所有前置任务完成。
- 手动启动：可以直接启动。

### 19.6 新建节点的上级显示为根目录

没有选中节点时，顶部“新建”默认使用根目录。

选中 444 后重新点击顶部“新建”，上级应自动选择 444。如果仍显示旧值：

1. 按 Ctrl+F5 强制刷新。
2. 确认上传了最新的 ProjectManagement.php。
3. 确认 project_management/app.js 是最新版本。

### 19.7 页面没有样式或脚本

确认整个 project_management 目录已经上传，包括：

- app.js
- style.css
- schema.sql
- install.php
- migrate_paused_status.sql

然后清理浏览器缓存。

### 19.8 同事电脑没有项目数据

项目文件和数据库是两部分：

- 上传 PHP、CSS、JS 只能得到功能。
- 项目、模板、角色、任务和日志保存在数据库中。

部署到新电脑时，必须同时恢复系统文件和数据库备份。

## 二十、更新和备份

### 20.1 更新前备份

建议备份：

- ProjectManagement.php
- project_management/ 目录
- 达和数据库

### 20.2 更新顺序

1. 备份旧文件。
2. 上传新的 ProjectManagement.php。
3. 上传新的 project_management/ 目录。
4. 如果菜单有更新，再上传 index.php。
5. 如果有数据库结构变更，再执行对应 SQL 文件。
6. 退出并重新登录系统。
7. 检查模板、实例、任务树、状态和甘特图。

### 20.3 数据库备份重点

项目管理数据主要位于 pm_ 开头的表中。完整迁移时不要只备份 pm_projects，还要包含模板、任务、角色、依赖、输入输出和日志表。

## 二十一、日常使用建议

- 项目编码保持统一规则，例如客户简称加年份和流水号。
- 模板名称不要写具体客户和临时日期，具体信息放到项目实例。
- 模板确认后再创建项目实例，避免频繁修改正在执行的项目结构。
- 任务开始前确认负责人、前置依赖和计划日期。
- 项目暂停时记录暂停原因，恢复后及时调整计划。
- 不要直接删除有下级任务的节点。
- 项目完成前检查所有任务、输入输出和交付物。
- 出现状态异常时，优先查看项目操作日志，不要直接改数据库状态。

## 二十二、当前功能边界

当前版本覆盖：

- 项目模板
- 任务模板
- 项目实例
- 任务树和折叠展开
- 项目和任务状态
- 角色分配
- 前置依赖
- 输入输出
- 甘特图
- 项目跟踪
- 操作日志

以下能力目前不属于本模块的独立功能：

- 与文档/物料模块的检入、检出和版本联动。
- 项目实例文件夹的独立数据管理。
- 根据销售、采购或生产单据自动生成项目任务。

扩展这些能力前，应先确认相关业务模块接口和数据权限，避免重复建设数据。
